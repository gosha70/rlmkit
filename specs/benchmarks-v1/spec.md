# Spec — Reproducible benchmarks v1

## 1. Problem
The README's "Where RLMKit shines / Not a fit" section and the announcement plan rely on the paper's numbers and on anecdotes (8 MB payloads on DGX Spark). Newsletters, HN and skeptical engineers will ask "show me the numbers, on which models, at what cost." The repo has an unused `benchmark/` package (dataset/runner/report over `strategies/`) and a toy `benchmarks/sample_benchmark.yaml`, but no public results and no way to reproduce any.

## 2. Goals / non-goals
**Goals**
- G1 A runner (`benchmarks/run_benchmark.py` or `rlm-studio bench` — see OQ-1) that executes a YAML-defined benchmark across a provider list × engine list using the *same* code paths as the Compare matrix (`RunMatrixComparisonUseCase`), records to the telemetry store, and emits JSON + a Markdown table.
- G2 A public long-document task set (`benchmarks/longdoc-v1.yaml`, ≥12 cases): mixed lengths (~5K, ~50K, ~150K+ tokens), tasks: needle-in-haystack fact, multi-section synthesis, counting/aggregation, "not in document" refusal; each with `expected_answer` and a rubric hint. Sources: permissively licensed public texts (Project Gutenberg, RFCs, US government reports, this repo's own docs).
- G3 Scoring: exact/contains match where applicable + LLM-judge pointwise score using the existing `prompts/judge_pointwise.yaml`, judge model fixed and named; report both.
- G4 `BENCHMARKS.md` at repo root: methodology, date, exact model IDs/versions, hardware for local runs, per-provider × engine table (accuracy proxy, judge score, tokens in/out, cost, TTFT p50, wall time), total cost to reproduce, known caveats. Regenerated by the runner — no hand-edited numbers.
- G5 Coverage: ≥3 providers — one local (Ollama or vLLM on DGX Spark; model named), two cloud (e.g. OpenAI + Anthropic small/cheap tier) — × {direct, rag, rlm, rlm_official (if `interop` landed)}.

**Non-goals**
- Not a leaderboard, not a claim about the paper's benchmarks (OOLONG/BrowseComp-Plus); the page states this explicitly.
- No paid or private datasets; no more than ~$25 total reproduce cost at cheap-tier cloud models (documented).
- No new UI in this cycle (the runner writes to telemetry, so results are viewable in Dashboard/Traces already).

## 3. Functional requirements
| ID | Requirement |
|---|---|
| FR-1 | Runner CLI: `--config benchmarks/longdoc-v1.yaml --providers openai:gpt-4o-mini,anthropic:claude-haiku-…,ollama:qwen3:… --engines direct,rag,rlm,rlm_official --judge openai:gpt-4o-mini --out results/<date>/` → `results.json`, `results.md`, `BENCHMARKS.md` section regenerated between markers. |
| FR-2 | Reuses `src/rlmstudio/benchmark/dataset.py` (extend `BenchmarkCase` with `min_tokens`, `task_type`, `rubric_hint`), replaces the strategy-based `runner.py` internals with a matrix-use-case driver (or adds a new `matrix_runner.py` and deprecates the old one — see OQ-2), extends `report.py` with the Markdown table and per-engine aggregates (accuracy, judge mean, cost, tokens, TTFT p50 from trace telemetry). |
| FR-3 | Judge: pointwise via `judge_pointwise.yaml` through `LLMPort`; judge model + prompt version recorded in results. |
| FR-4 | Budgets per case (steps, wall-clock, cost cap) from the YAML; failures classified with the existing outcome classifier and counted (not silently dropped). |
| FR-5 | Determinism aids: temperature 0 where the provider allows; seed recorded; three runs for the headline table with mean ± range on judge score (cloud) — single run for local if time-bound, stated. |
| FR-6 | Docs: `BENCHMARKS.md`, README "Where RLM Studio shines" cites the table; `docs/rlm-studio-guide.md` gets a "Reproducing the benchmarks" section; CHANGELOG. |
| FR-7 | CI: a `bench-smoke` step runs the runner on 2 tiny cases with the in-memory fake LLM (no network) to keep the runner from rotting. |

## 4. Constraints
- No hardcoded model IDs in code — all in the YAML/config and CLI flags.
- Judge prompt lives in `prompts/` (already does); no inline rubric strings.
- Dependency rule holds: runner lives in `application`/`benchmark` layer and infrastructure adapters are injected.

## 5. Acceptance criteria
- AC-1 Fresh clone, documented env vars, `uv run … --config benchmarks/longdoc-v1.yaml …` completes and regenerates `BENCHMARKS.md`; numbers match the committed page within stated variance.
- AC-2 `BENCHMARKS.md` includes: date, model IDs, hardware, table per provider × engine, total cost, caveats, "not the paper's benchmarks" note, link to the paper and `alexzhang13/rlm`.
- AC-3 CI `bench-smoke` green with fakes; no network.
- AC-4 Every reported cell has ≥12 cases; failures are counted in a "failed / timed out" column.

## 6. Open questions (defaults)
- OQ-1 Entry point: default `rlm-studio bench` subcommand (reuses the CLI dispatcher) with `benchmarks/run_benchmark.py` as a thin wrapper; fallback script-only if CLI time is short.
- OQ-2 Old `benchmark/runner.py` (strategy-based): default — keep public API, delegate to the matrix driver; remove in v1.1 if unused.
- OQ-3 Local model choice: default the DGX-Spark vLLM model documented in `docs/hosts/dgx-spark-vllm.md`; Ollama `qwen3` family on a laptop as the "anyone can reproduce" row.
